# kaidem-ai/.github

Общие настройки организации Kaidem AI на GitHub: формы задач (Задача, Правка клиента, Баг) и шаблон PR.
GitHub применяет их ко всем репозиториям организации, у которых нет своих.

Своя папка `.github/ISSUE_TEMPLATE` в репозитории полностью заменяет эти формы.

## Метки и доски

- `labels.json` — общий набор меток (он же — метки организации по умолчанию в Settings → Repository defaults).
- `scripts/setup-repo.sh <owner/repo>` — настроить новый репозиторий: squash-merge, удаление веток, метки (из шаблона это не копируется).
- `scripts/sync-labels.sh <owner/repo> [extra.json]` — привести метки репозитория к набору.
- `boards.json` — какие репозитории относятся к какой доске: все репозитории организации (`org`), кроме служебных (`exclude`), плюс личные (`repos`). Новый служебный репозиторий — добавить в `exclude`.
- `scripts/sweep-boards.sh` — добавить на доски открытые задачи, которых нет ни на одной доске (Auto-add на бесплатном тарифе — один репозиторий, личные репозитории к доске организации не привязываются).
- `.github/workflows/sweep-boards.yml` — запускает `sweep-boards.sh` каждые 10 минут. Без LLM, просто скрипт. Нужен секрет `BOARDS_TOKEN` (classic PAT, scope `repo` + `project`).

## Доска Work

`scripts/reconcile-work.py` сверяет открытые issues активных репозиториев с Work и заполняет Category по `boards.json`. Для репозитория без сопоставления категория автоматически не задаётся; вручную заданные Clients/Own сохраняются, а карточки без категории видны в Unclassified. В `categories` добавляй явное соответствие Clients или Own; карта является источником категории. Архивные карточки не изменяются. Workflow запускается по расписанию и сообщает об ошибке при отсутствии токена или сбое.

## Локальная сверка Work на Mac

`scripts/local-work-sync.py` запускает ту же сверку через существующую авторизацию `gh`. Он скачивает `boards.json` и сверочный скрипт с одного commit `main`, не хранит токен и не допускает параллельных локальных запусков. Состояние последнего запуска хранится в `~/Library/Application Support/Kaidem/work-sync/last-run.json` с доступом владельца. На Mac используется LaunchAgent `ai.kaidem.work-sync` с интервалом 10 минут; при выключенном или спящем Mac он не работает. GitHub Actions остаётся резервной проверкой. Таймер не является реакцией на событие создания задачи и не гарантирует срок появления карточки.

Рабочая доска содержит представление «Зависимости» с фильтром открытых задач с незакрытой GitHub-зависимостью. Список не выявляет неоформленные зависимости и не меняет статус задачи.
